# Комплект первого запуска VPS

Исходный ZIP находится в `releases/AI-Cartoon-Studio-VPS-*.zip`. В нём приложение, интерфейс, установщик, Compose, тесты, примеры и документация. Секреты, локальная БД, результаты рендера и резервные копии `.env` не включаются. Рядом — SHA-256 архива, внутри — BUNDLE_MANIFEST.json с хешами файлов.

## Что подготовить

1. Ubuntu 24.04 x86_64 с Docker Engine и Compose. Установщик не меняет системные репозитории и не удаляет конфликтующие пакеты. Если Docker ещё нет, используйте [официальную инструкцию Docker](https://docs.docker.com/engine/install/ubuntu/).
2. Домен с DNS на этот VPS и доступные порты 80/443. Другие сервисы, занимающие эти порты, автоматически не останавливаются.
3. Telegram Bot Token и числовой ID владельца.
4. Cloudflare Account ID и API Token с доступом Workers AI в Free-аккаунте без платёжного подключения. Мастер первого запуска использует этот провайдер; Router также поддерживает отдельно настраиваемые Gemini/Ollama. Фактическая доступность, тариф и квоты аккаунта проверяются владельцем, а не выводятся из слова Free в конфигурации.

Маршрут первого запуска обновлён на [Qwen 3.8 27B в Cloudflare](https://developers.cloudflare.com/workers-ai/models/qwen3.8-27b/): установлен низкий reasoning_effort и предел ответа. Прежний стартовый ID модели не используется новым мастером. Перед подключением всё равно проверьте [условия Free и ограничения моделей](https://developers.cloudflare.com/workers-ai/platform/pricing/); код не проверяет billing аккаунта за владельца.

Покупок и платных запросов проект не выполняет. Сервер и домен не предоставляются самим кодом.

## Одна команда на подготовленном VPS

Распакуйте ZIP в отдельную папку, войдите по SSH интерактивно и в этой папке выполните:

```bash
sudo python3 deploy/start.py
```

Мастер скрыто запросит доступы, создаст новые отдельные токены, `.env` и секретный `worker-connection.env`, соберёт Docker-образ, проверит конфигурацию внутри контейнера и запустит сервисы. Затем добавит начального персонажа Макса, не перезаписывая существующий паспорт, и проверит HTTPS `/health`.

Существующий `.env` не перезаписывается. Если эта студия уже запущена, повторный запуск не обновляет и не перезапускает её. Работающие чужие сервисы не останавливаются. Установщик не удаляет контейнеры/тома и оставляет проверочный остановленный контейнер для диагностики. Имена проекта Docker зависят от каталога; не переносите уже запущенный проект в другую папку без отдельного плана миграции.

Перед запуском приложения можно использовать подготовленный вручную `.env` вместо мастера. Заполните его по примеру. При неполных настройках контейнерная диагностика остановит первый запуск.

## Озвучка без отдельной модели

Для функционального первого цикла мастер явно включает `STUDIO_TTS_FALLBACK=espeak`. eSpeak NG устанавливается в образе и синтезирует русскую речь на CPU VPS без API и отдельной модели. **Тембр роботизированный**: это резерв, не обещание естественного актёрского голоса. Качество и длительность нужно проверить на реальной серии до публикации. [Исходный проект eSpeak NG](https://github.com/espeak-ng/espeak-ng).

Позже можно положить лицензированный Piper-голос с ONNX/JSON в `voices/` и указать `PIPER_MODEL=/app/voices/имя.onnx`. Если конкретный Piper-голос выбран, но недоступен, система ждёт его и не заменяет молча резервом. Изменение темпа резервной речи учитывается в ключе переиспользования WAV.

## Подключение Lenovo

С VPS безопасно скачайте **только** `worker-connection.env`, например через SFTP. Этот файл содержит HTTPS-адрес и отдельный Worker-токен. Он не содержит ключей Telegram/модели или токена владельца API. Не отправляйте файл в чат и не публикуйте.

В папке проекта на Lenovo:

```powershell
python scripts/connect_worker.py "C:\путь\worker-connection.env" --apply
python -m studio worker
```

Также доступен пункт 6 в `Запуск.cmd`. Применение создаёт секретную резервную копию прежнего `.env`, меняет только параметры подключения Worker и сохраняет прочие настройки. Серверная подготовка на Lenovo отключается. Без `--apply` выполняется только проверка файла, без записи.

Для автозапуска Worker подготовлен `scripts/install-worker-autostart.ps1`; его пользователь запускает отдельно после успешного подключения. Существующее задание Планировщика не перезаписывается.

## Первый цикл

Откройте бота: `/start`, затем `/ideas`. ИИ предложит новые сюжетные ситуации «А что, если…»; вы выбираете идею, читаете сценарий и согласуете подготовку. По умолчанию общий генератор запускается также ежедневно. Для учебных историй о ЧС сохраняется отдельная проверка источников. Worker забирает готовый пакет и выполняет только финальный рендер. Проверки качества и явное согласование публикации не отключаются.

YouTube/TikTok не включаются мастером автоматически. Это не мешает создавать MP4 и скачивать их для ручной публикации.

## Что ещё нужно подтвердить на сервере

Локально проверены код, архив, скрытие секретов, идемпотентность настройки, сохранение конфигурации Worker, диагностика и существующий рендер-конвейер. Docker в доступной среде отсутствует: реальная сборка образа, eSpeak/Piper на Linux, расход RAM, доступ модели, Telegram, HTTPS и синхронизация подтверждаются при первом запуске VPS. Успешная статическая проверка не заменяет эти проверки.
