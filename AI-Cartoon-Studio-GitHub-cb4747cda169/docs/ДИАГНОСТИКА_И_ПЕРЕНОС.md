# Проверка готовности и перенос

Диагностика работает без сетевых запросов, не запускает модели, не генерирует материалы и не показывает значения секретов. Она проверяет наличие и форму настроек; авторизация поставщика, billing, DNS, сертификат, совместимость голоса и качество речи требуют отдельных реальных проверок.

## Lenovo

```powershell
python -m studio doctor --profile worker
```

Проверяет Windows, FFmpeg/ffprobe, отдельный токен Worker, HTTPS-адрес VPS и отключение серверной подготовки на Lenovo. Ключи Telegram и моделей на компьютере рендера не требуются. NVENC не запускается при диагностике: его фактическую совместимость проверяет Worker при рендере.

## Сервер без контейнеров

```bash
python -m studio doctor --profile server
```

Проверяет раздельные токены, серверный режим, Telegram, адрес панели, маршрут модели, Piper и пару файлов голоса ONNX/ONNX.JSON. Наличие файлов не означает проверенную лицензию и пригодность русской речи.

## Подготовка Compose

```powershell
python -m studio doctor --profile deployment
```

Проверяет файлы проекта, совпадение STUDIO_DOMAIN и STUDIO_PUBLIC_URL, параметры Telegram/модели и голос. Путь `/app/voices/имя.onnx` сопоставляется с локальным `voices/имя.onnx`. Серверный режим в Compose включается явно внутри контейнеров; локальный .env Lenovo из-за этого менять не нужно.

В базовом Compose нет Ollama: localhost контейнера не означает localhost хоста. Диагностика сообщает об этом отдельно. Не включайте Ollama на Lenovo для обхода отсутствия серверной модели.

Docker в текущей среде отсутствует, поэтому контейнерная сборка ещё не подтверждена. При подключении VPS нужно фактически выполнить build, проверить запуск сервисов, HTTPS, голос и модель.

## Панель и автоматическая проверка

В «Настройках» появилась кнопка «Проверить настройки сервера». Доступ разрешён только владельцу. Состояния: «Есть», «Нужно настроить», «Проверить», «Выключено». Выключенная публикация не мешает подготовке и рендеру.

```bash
python -m studio doctor --profile server --json --strict
```

JSON содержит summary и checks, но не значения токенов. `live_verified` всегда false: диагностика не подтверждает реальные интеграции. С `--strict` код выхода 2 означает недостающие настройки. Без него можно спокойно изучить отчёт до подключения сервисов.

## Python-пакет без сети

```bash
python scripts/build_offline_package.py
```

Локальный setuptools собирает wheel в новый каталог reports/package-build-*. Зависимости не скачиваются и не устанавливаются. Проверяется наличие модулей и статического интерфейса, отсутствие .env/данных и побайтовое совпадение исходников внутри пакета. Docker-файлы, документация и примеры остаются рядом в исходном проекте, а не внутри wheel.

Python-пакет собран на Windows как py3-none-any. Это подтверждает упаковку Python-кода, но не тестирование Ubuntu, Docker-образа или нативных зависимостей Piper/FFmpeg. Для первого развёртывания используйте исходный проект с compose.yaml и инструкцией README.
