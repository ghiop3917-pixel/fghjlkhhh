# AI Cartoon Studio

Студия с отдельным сервером подготовки и Windows Render Worker. Проект находится в этой папке; файлы и интеграции других проектов не менялись.

**Сейчас:** расширен локальный конвейер, добавлены послойная анимация, проверки и исправления, планы публикации и защищённая очистка. VPS и реальные аккаунты не подключены. Точный объём, проверки и ограничения — в [состоянии комплекта](docs/ГОТОВНОСТЬ_БЕЗ_VPS.md). Полная работа на внешних сервисах ещё не подтверждена.

В Telegram добавлены запуск/перенос рендера, действительные этапы сборки, готовый ролик с семью проверками и замечаниями, тихие часы, ежедневная сводка и контроль связи/места Lenovo. [Управление из Telegram](docs/УДОБСТВА_TELEGRAM.md).

[TikTok-мемы для сюжетов](docs/МЕМЫ_TIKTOK.md): фоновая проверка свежих RSS-публикаций и ссылки владельца. Анализируются описания, прямой просмотр TikTok-видео не реализован.

## Быстрый старт на Lenovo

Откройте `Запуск.cmd`. Доступны проверка окружения, безопасное создание `.env`, запуск Worker и тесты. В рабочем режиме ПК не ищет тренды и не генерирует материалы.

Если зависимости ещё не установлены, создайте отдельное окружение:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -e ".[test]"
.venv\Scripts\python -m studio doctor
python scripts/setup_env.py
```

В текущей среде необходимые библиотеки уже были установлены. Разработчик не устанавливал глобальные пакеты, голоса и модели. Если используете `.venv`, запускайте команды через её Python; `Запуск.cmd` использует Python из PATH.

В `.env` Windows нужны:

```dotenv
STUDIO_SERVER_ENABLED=false
STUDIO_API_URL=https://ВАШ-ДОМЕН
STUDIO_WORKER_TOKEN=ТОТ_ЖЕ_ОТДЕЛЬНЫЙ_ТОКЕН_ЧТО_НА_VPS
STUDIO_WORKER_ID=lenovo-render-1
STUDIO_ENCODER=auto
```

Секрет владельца API, ключи моделей и Telegram-токен на Lenovo для рендера не нужны. Не пересылайте `.env` в чат, не публикуйте его и не кладите в архивы для третьих лиц. Существующий `.env` генератор не перезаписывает.

```powershell
python -m studio worker
```

До подключения VPS Worker ожидает соединения. Не назначайте ему публичный HTTP: удалённый сервер требует HTTPS. Автозапуск подготовлен в `scripts/install-worker-autostart.ps1`; его нужно выполнить вручную после настройки. Разработчик не менял Планировщик Windows.

## Подключение VPS

**Самый короткий путь:** загрузите свежий ZIP на чистый Ubuntu 24.04 и выполните `sudo python3 ИМЯ_АРХИВА.zip`. Docker, сервисы и секретный комплект Lenovo готовятся автоматически. [Инструкция одной команды](docs/ОДНА_КОМАНДА_VPS.md).

Подготовлен исходный ZIP и мастер первого запуска: [короткая инструкция](docs/БЫСТРЫЙ_ЗАПУСК_VPS.md). На VPS с Docker запускается `sudo python3 deploy/start.py`; мастер запрашивает доступы скрыто, сохраняет существующие настройки и создаёт отдельный файл подключения Lenovo. Для первого цикла доступен явно включаемый роботизированный резерв eSpeak NG, поэтому отдельная модель Piper не обязательна.

Перед переносом выполните `python -m studio doctor --profile deployment`. Для Lenovo есть профиль `worker`, для запущенной серверной среды — `server`. В панели диагностика находится в «Настройках». [Диагностика и проверка пакета](docs/ДИАГНОСТИКА_И_ПЕРЕНОС.md).

Подготовлены `compose.yaml`, Dockerfile и HTTPS-прокси Caddy. Они не запускались на сервере и не проверялись Docker-сборкой в текущей среде, где Docker отсутствует. Фактическая совместимость с выбранным VPS и его RAM проверяется при развёртывании.

1. На Ubuntu 24.04 установите Docker Engine с Compose из официального источника. Согласуйте аренду сервера отдельно: покупок проект не совершает.
2. Скопируйте исходники без `data/`, `worker-data/`, `.venv/`, `reports/` и локального `.env`. Создайте серверный `.env` командой `python3 scripts/setup_env.py` или вручную из примера. Создайте каталог `voices/`.
3. Направьте DNS домена на VPS. Откройте 80/443; SSH ограничьте своим доступом. В `.env` задайте `STUDIO_DOMAIN=ваш.домен` и `STUDIO_PUBLIC_URL=https://ваш.домен`. Порт API наружу не публикуется.
4. Задайте `TELEGRAM_BOT_TOKEN` от BotFather и числовой `TELEGRAM_OWNER_ID`. Бот работает только в личном чате этого владельца. Не запускайте два polling-процесса одного бота.
5. Подключите **один** разрешённый бесплатный провайдер. Для облаков требуется `STUDIO_CLOUD_ENABLED=true` и отдельное подтверждение Free-аккаунта. Сначала проверьте доступность модели, регион, квоты, отсутствие платёжного подключения и условия обработки сценариев. Gemini по умолчанию не выбран. Для Ollama используется отдельный серверный localhost; в Compose встроенного Ollama нет. `127.0.0.1` внутри контейнера — сам контейнер, поэтому при выборе Ollama используйте native-развёртывание либо спроектируйте отдельное безопасное подключение.
6. Для естественнее звучащего голоса выберите лицензированную модель Piper. Положите `.onnx` и сопутствующий `.onnx.json` в `voices/`; запишите `PIPER_MODEL=/app/voices/имя.onnx`. В голосах персонажей используйте пустую строку для общего голоса или отдельный путь в `/app/voices/`. Образ включает Piper и резервный eSpeak NG, но не скачивает модели Piper и не выбирает за вас их лицензию. Мастер по умолчанию включает резерв с роботизированным тембром.
7. Укажите разрешённые публичные HTTPS RSS в `STUDIO_RSS_URLS`, через запятую. Пустое значение означает отсутствие источников. Поддержка других платформ не имитируется.
8. Запустите:

```bash
docker compose build
docker compose up -d
docker compose ps
docker compose logs --tail=50 api production bot
```

Команды здесь — инструкция для будущего запуска, а не отчёт об исполнении. Общие ограничения контейнеров около 1.5 ГБ не гарантируют работу голоса/LLM на 2 ГБ RAM. Сначала замерьте потребление, не запускайте тяжёлые модели параллельно. Для Ubuntu без Docker есть отдельные команды `python -m studio api`, `production`, `bot`; нужны виртуальное окружение, FFmpeg, шрифт DejaVu и внешний HTTPS-прокси.

9. Передайте **только Worker-токен** и HTTPS-адрес в `.env` Lenovo. Запустите Worker. Включите `/mode AUTO` в Telegram.
10. Откройте `/app` в личном чате бота. Mini App проверяет подписанный initData. Через 15 минут потребуется переоткрыть приложение. Локально можно войти токеном владельца; он хранится только в памяти вкладки.

## Первый полноценный цикл

Основной формат расширен до **«А что, если…»**: ИИ сам придумывает разные ситуации, миры и конфликты без закрытого списка тем. Команда `/ideas`, кнопка «Придумать новые сюжеты» и ежедневный серверный планировщик. [Как работает общий генератор](docs/А_ЧТО_ЕСЛИ.md).

Добавлен отдельный формат **«Критические ситуации» — сюжетные серии с советами**: ядерный взрыв, подозрительный предмет, вооружённое нападение. В панели есть выбор темы и обязательная проверка советов; в Telegram — `/emergency`. [Описание формата, источники и готовые сценарии](docs/КРИТИЧЕСКИЕ_СИТУАЦИИ.md).

1. В панели «Персонажи» создайте хотя бы один паспорт, например `max`. Рисователь поддерживает четыре причёски, три телосложения, три вида одежды, три формы лица, тон кожи, очки, серьги и цепочку. Кнопка «Предпросмотр» показывает внешность и три эмоции до подготовки серии. Произвольное описание и нейросетевые референсы поддерживаются не полностью.
2. Через `/find` получите темы. Для криминального вымысла используйте события только как вдохновение: не приписывайте реальные преступления людям.
3. Выберите тему кнопкой. Продюсер поставит сценарий в очередь; при отсутствии модели задача будет ожидать. Самостоятельный сценарий можно импортировать в панели JSON или `/script JSON`.
4. Прочитайте сценарий и нажмите «Согласовать подготовку». Подготовка создаст PNG, голосовые WAV, оригинальный синтезированный музыкальный фон, ASS, обложку и manifest. Музыку можно отключить полем сценария `"music":"none"`.
5. Worker скачает пакет, проверит SHA-256, соберёт MP4 и вернёт его. На текущем FFmpeg/драйвере используется резервный libx264: NVENC-тест завершился несовместимостью API.
6. Сервер полностью декодирует видео для технического QC. После этого просмотрите и прослушайте ролик в панели и явно подтвердите семь проверок. Динамические субтитры имеют приблизительные интервалы слов и требуют проверки синхронизации.
7. Скачайте MP4 для ручной публикации. YouTube-адаптер допускает только отдельно согласованную приватную загрузку. Для этого нужны OAuth, `YOUTUBE_ENABLED=true` и разрешение на конкретный файл/метаданные. Публичность меняет владелец в YouTube Studio. При неопределённом результате повтор заблокирован до сверки.
8. TikTok: ручной экспорт либо отдельно включаемая доставка в черновики через разрешённое приложение и OAuth `video.upload`. Автор завершает публикацию в TikTok. Direct Post не включён из-за ограничений частного внутреннего применения.

Сценарная правка создаёт отдельную редакцию, старая сохраняется. Подготовка переиспользует проверенные изображения и WAV предыдущей редакции: изменение реплики пересоздаёт её озвучку, изменение внешности/эмоции — соответствующие изображения. Смена содержимого файла голоса по прежнему пути также пересоздаёт аудио. Порядок сцен может меняться; субтитры и общий тайминг всегда пересчитываются. Музыка переиспользуется при неизменной общей длительности. Исходный пакет не изменяется; повреждённый материал создаётся заново. Старые пакеты без ключей входных данных безопасно пересоздаются. Переиспользование касается подготовки; финальный рендер новой редакции выполняется полностью.

Уже запущенная старая задача не отменяется автоматически. Перед согласованием публикации проверяйте ID редакции.

Правки обычным текстом доступны в диалоге с продюсером или `/agent роль текст`: агент предлагает конкретные объекты. В панели «Команда агентов» можно открыть старое (`before`) и новое содержимое и подтвердить применение. В боте — `/proposal ID` и кнопка подтверждения; большие правки проверяются в панели. При конфликте версий вся правка откатывается транзакцией и требует нового предложения. Постоянные правила также меняются только после этого явного подтверждения.

## Внешность и предпросмотр

Для точного управления 2D-внешностью добавьте в паспорт необязательный блок `render_style`:

```json
{"haircut":"long","build":"slim","outfit":"hoodie","face_shape":"oval","skin_color":"#e4af8c","glasses":"round","earrings":false,"necklace":false}
```

Допустимы haircut: short/long/shaved/curly; build: slim/regular/broad; outfit: jacket/hoodie/tshirt; face_shape: oval/round/angular; glasses: none/round/square. Без блока распознаются простые слова в старых паспортах: «длинные», «кудрявые», «бритая», «худощавое», «крепкое», «худи», «футболка», «круглое», «угловатое», «очки», «серьги», «цепочка». Явный `render_style` имеет приоритет над текстовым описанием. Предпросмотр возвращается из памяти и не создаёт временных файлов на диске. Это фронтальный рисованный риг; другие ракурсы пока не реализованы.

## Аналитика и память

Метрики можно вносить в панели. По умолчанию неизвестные значения — `null`, а не нулевые «измерения». Для чтения своих YouTube-данных включите `YOUTUBE_ANALYTICS_ENABLED=true`, выдайте OAuth-права YouTube readonly и Analytics readonly и включите соответствующие API в проекте. Адаптер получает просмотры, доступное среднее удержание и подписки; досмотры и повторы не выводятся из предположений. Реальный доступ ещё не проверялся.

Чтение метрик: `POST /api/analytics/ID_СЕРИИ/youtube-sync`. Если предыдущая серия имеет YouTube video_id, чтение запускается перед созданием следующего сценария при включённой опции. Данные Analytics могут приходить с задержкой.

Комментарии: `POST /api/analytics/comments` с `{"series":"main","comments":["..."]}`. Исходные комментарии не сохраняются в БД/логах; сохраняется сводка модели. Автоматический адаптер YouTube забирает до 100 последних верхнеуровневых комментариев. Это не полный архив всех веток. При включённых облаках комментарии отправляются выбранному разрешённому поставщику.

Архив серий содержит только название сезона, название серии и полный сценарий. Сюжетная память, паспорта, аналитика и события хранятся отдельно. В модель не отправляется весь архив. Недельный отчёт ставится по понедельникам UTC; ежедневный поиск — с 07:00 UTC (10:00 Москвы), настраивается в `.env`.

## Восстановление и резервные копии

- Выключили Lenovo: подготовка на VPS продолжается, render остаётся в очереди.
- Обрыв во время рендера: после истечения аренды задача выдаётся заново; старый результат не принимается. Сборка возобновляется с пакета, не с последнего видеокадра.
- Три ошибки: задача `failed`, бот отправляет уведомление. Отсутствие модели/голоса — ожидание настройки без расходования попыток.
- `POST /api/backup` или `/backup` — согласованная копия SQLite через backup API. Планировщик дополнительно создаёт ежедневную копию БД. **Файлы пакетов, эталоны, голоса и MP4 нужно резервировать отдельно.** Копии на том же диске не защищают от потери VPS.
- Удаление отключено. `/api/episodes/ID/cleanup-plan` только показывает кандидатов и не удаляет файлы. Автоматическую очистку нужно отдельно реализовать/согласовать после проверки публикации.

## Проверки

```powershell
python -m pytest -q
$env:STUDIO_RENDER_TEST='1'
python -m pytest -q tests/test_media.py::test_full_real_render_and_decode
python -m ruff check studio tests scripts
node --check studio/static/app.js
python scripts/check_ui.py
```

Последняя команда использует установленный Edge и Playwright, поднимает временный локальный API, блокирует внешнюю сеть браузера и сохраняет скриншоты в `reports/`. Это разработческий тест, не запуск серверной подготовки на Lenovo. Кеши и временные тестовые материалы автоматически не очищаются.

Фактические результаты текущей проверки записаны в [отчёте](reports/ПРОВЕРКИ.md). Полноценная эксплуатация не подтверждена без VPS, настоящей речи, внешних API и проверки владельцем.
